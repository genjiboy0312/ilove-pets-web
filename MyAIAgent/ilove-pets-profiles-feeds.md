# 프로필·작성·My 연결과 피드/스토리 개선

2026-10-15. 다음 계획의 1차·2차를 함께 구현했다.

## 사용 흐름

- 로그인 후 My는 클라우드 계정 화면을 먼저 표시한다. `이 기기` 탭으로 기존 데모·로컬 기록을 계속 사용할 수 있다.
- My의 `프로필 수정`에서 고유 사용자 이름(영문 소문자·숫자·밑줄 3~30자), 닉네임, 소개, 프로필 사진을 저장한다. 편집 필드는 저장 시 공개되며 이메일·시간대·비공개 글·성장 기록은 공개하지 않는다. 아직 게시물도 공개 프로필 저장도 없는 계정은 외부 프로필 조회에 나오지 않는다.
- `/users/:username`에서 공개 프로필·공개 게시물·팔로우 현황을 본다. 피드와 댓글의 사용자 이름을 누르면 해당 프로필로 이동한다. 공개 글의 작성자 사진도 프로필 사진을 사용한다.
- My에서 내 스토리를 관리하고, `내 서버 게시물·펫·성장 기록`을 열면 기존 서버 기록을 수정·삭제·공개 전환할 수 있다. 공개 게시물 수는 공개 글만 센다.
- 작성 화면의 `저장 위치`에서 이 기기/클라우드를 선택한다. 클라우드에는 해당 계정의 펫과 사진 게시물을 비공개로 저장하고, 저장 후 클라우드 기록에서 명시적으로 공개한다. 로컬 자료를 자동으로 이전하거나 병합하지 않는다.
- 홈의 이 기기/공개 선택 및 공개 피드의 전체/팔로잉 선택을 계정별로 기억한다. 다른 계정과 비로그인 사용자의 설정은 분리한다. 저장 공간 오류가 나도 피드 선택은 계속 사용할 수 있다.
- 스토리 사진을 좌우로 밀어 이전/다음으로 이동한다. 기본 이미지 드래그를 막아 데스크톱에서도 동작한다. 사진 요청 실패 시 다시 불러오기를 제공한다. 기존 24시간 만료·팔로워 권한·자동 넘김·일시 정지는 유지한다.

## 서버 계약

`202610150004_profiles_feeds.sql`을 개발 Supabase에 적용했다. 이전 마이그레이션을 다시 실행하지 않는다. 기존 `social-media` 프록시와 검증된 이미지 처리 경로를 그대로 사용하며 프록시의 가시성 RPC가 공개 프로필 사진도 확인한다.

프로필은 사용자 자신만 수정하며 버전 충돌·고유 이름을 검사한다. 프로필 사진은 자신의 ready 상태 `profile_avatar` 사진만 참조할 수 있다. 새 사진을 지정한 뒤 이전 사진을 정리 큐에 넣고 실제 정리 성공 후 용량을 회수한다. 현재 프로필 사진은 일반 미사용 사진 삭제에서 보호한다. 제거·교체된 사진에는 새로운 공개 프록시 요청이 404를 반환한다. 이미 내려받은 사진을 회수한다는 의미는 아니다.

공개 프로필 projection에는 이메일·시간대·계정 관리 상태를 포함하지 않는다. 버전은 본인만 받는다. 작성자·팔로잉 조건은 서버에서 페이지 제한보다 먼저 적용한다. 기존 3개 인자 피드 호출도 새 기본값 인자와 호환된다. 프로필·작성·My의 비동기 상태는 계정별로 화면을 다시 생성하며 작업별 JWT를 고정한다.

## 검증 근거와 남은 확인

- 로컬 PostgreSQL에서 공개 전 동작, 익명 공개 필드, 사진 소유권, 중복 이름·오래된 수정 거절, 사진 교체·삭제 큐, 활성 사진 보호, 팔로잉/작성자 필터와 20개 커서 경계를 검사했다.
- 실제 임시 A/B 계정과 PNG 업로드·WebP 처리로 프로필 공개 필드·사진 조회, 외부 사진 참조 거절, 중복 이름·버전 충돌, 사진 제거 후 404와 팔로잉 필터를 확인했다. 기존 사진·공개 게시·댓글·좋아요·스토리 흐름도 통과했고 임시 데이터·파일·계정을 모두 정리했다.
- 앱 단위 검사 37개 파일/193개, 서버 검사 34개 통과. 작성 화면 단위 검사는 새 Router/저장 위치 그룹에 맞춰 보완했다.
- 브라우저에서 프로필 사진/닉네임 수정→공개 프로필 이동→클라우드 비공개 작성→My 확인, 피드 선택 기억·팔로우 해제 후 빈 목록, 스토리 스와이프와 사진 실패 재시도를 검사한다. 모의 API 화면 검사와 실제 HTTP 권한 검사를 구분한다.
- 전체 Chromium 회귀 67개 통과 후, 추가 사진 실패 복구와 포커스/Escape 복구 및 모바일 탭 너비 수정까지 관련 3개를 다시 검사했다. 최종 관련 검사에는 사진 실패→재시도→정상 표시→키보드 닫기가 포함된다. 실물 휴대전화 검증으로 간주하지 않는다.
- 타입·변경 파일 린트·깨끗한 별도 출력 폴더 production build를 확인했다. 기존 Windows dist 파일 잠금과 약 868kB 번들 경고는 이번 범위에서 해결하지 않았다.

실제 휴대전화에서 두 계정을 번갈아 사용하는 확인, 이메일/복구·SMTP, 자동 만료 파일 정리, 알림·신고·차단·계정 삭제·로컬 자료 이전은 후속이다. 이번 기능에 알림이나 DM은 포함하지 않는다.
