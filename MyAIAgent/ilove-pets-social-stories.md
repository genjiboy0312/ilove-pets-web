# S3 공개 소셜과 팔로워 스토리

2026-10-15. S2 사진 게시글 저장의 실제 사용자 확인 이후 추가한 기능이다.

서버 `106e535`·앱 `d3872f7`·문서 `3440ed0`를 main에 푸시했고 Cloudflare Pages success를 확인했다. 실제 공개 주소의 375px Chromium에서도 스토리 목록 표시, 익명 공개 피드 RPC 200, 오류 안내 없음·가로 넘침 없음 검사가 통과했다. 공개 홈에서 바로 사용할 수 있다.

## 사용 방법

- 홈 상단의 `스토리 추가`에서 사진과 설명을 올린다. 로그인한 본인과 팔로워에게만 24시간 표시한다. 원형 사진을 누르면 뷰어가 열리고, 사진이 로드되면 5초 후 다음 스토리로 이동한다. 이전/다음 버튼, 방향키, Escape, 재생/일시 정지, 길게 누르기와 탭 비활성 시 정지를 지원한다.
- 홈의 `공개 피드` 탭에서 실제 서버 게시물을 본다. 기존 데모·로컬 피드는 `이 기기 피드`에 유지한다. 두 출처를 자동으로 섞지 않는다.
- `/cloud`의 게시물에서 `공개로 전환` → 공개 범위 확인 후 공개한다. 기존 글은 비공개를 유지한다. 게시물 상세 `/posts/:postId`에서 좋아요, 댓글 작성·삭제, 링크 복사를 사용한다. 작성자와 게시물 소유자만 댓글을 삭제할 수 있다.
- 공개 글의 작성자 또는 `친구 찾기`에서 팔로우한다. 공개 글을 작성한 계정만 검색 결과에 표시한다. 본인의 스토리 조회 수는 다른 사용자의 중복 조회를 한 번으로 센다. 팔로우 해제 시 해당 계정의 스토리 접근 권한도 사라진다.
- 첫 버전은 사진 스토리다. 영상·음악·스티커·DM 답장·하이라이트·차단/비공개 계정 팔로우 승인 기능은 포함하지 않는다.

## 서버와 공개 범위

`202610150003_social_stories.sql`을 S2 및 충돌 응답 수정 이후 한 번 적용한다. 개발 Supabase에는 적용을 마쳤고 `social-media` 함수도 배포했다. 기존 `cloud-media`의 실제 디코딩·WebP 정규화를 그대로 사용한다.

공개 피드와 댓글은 필요한 필드만 반환하는 RPC로 조회한다. 프로필 전체, 이메일·시간대, 비공개 펫·성장 기록·원본 Storage를 공개하는 테이블 정책은 추가하지 않는다. 쓰기는 검증된 계정·소유권을 확인하는 RPC만 사용하며 직접 테이블 접근은 차단한다. 공개 전환과 수정은 버전 충돌을 검사하고 HTTP 409를 반환한다.

공개/팔로워 사진은 `social-media?asset=...` 프록시가 매 요청마다 DB 공개 범위와 만료 시간을 검사한 뒤 정규화 파일만 응답한다. 익명은 공개 게시물 사진만, 팔로워는 활성 스토리 사진만 조회한다. CORS 허용 출처를 제한하며 `Cache-Control: private, no-store`로 응답한다. 비소유자에게 Storage 직접 읽기·장기 서명 URL 생성 권한을 추가하지 않는다. 이미 내려받은 사진을 회수하는 기능은 아니다.

스토리는 서버 시각으로 작성 후 24시간이 되면 즉시 신규 조회 대상에서 빠진다. 실제 객체 삭제와 용량 회수는 소유자가 홈을 방문하거나 새로고침할 때 만료 처리를 정리 큐에 넣고 기존 정리 함수로 수행한다. 상시 예약 작업은 아직 없으므로 만료와 물리 삭제를 같은 시점이라고 설명하지 않는다. 정리 실패 시 용량은 유지되고 재방문 시 재시도한다. 스토리에 사용 중인 사진은 미사용 사진 정리와 게시물 재사용에서 보호한다.

## 조회 범위와 검증

피드 20개·댓글 30개씩 커서 조회한다. 스토리는 최대 200개 활성 항목, 계정당 활성 스토리 20개, 팔로우 1000명, 계정당 댓글 시간당 60개로 제한한다. 사진 용량은 기존 계정 50MiB·프로젝트 800MiB 예산을 공유한다.

- 전체 앱 Vitest 36개 파일/190개 통과. 새 소셜 UI는 Playwright에서 별도로 검사했다.
- 서버 Node 검사 31개 통과. 공개/비공개 projection, 중복 좋아요·댓글, 팔로워 전용 스토리, 팔로우 해제, 만료, 조회 중복 방지, 원본 접근 및 미사용 사진 삭제 우회 차단을 포함한다.
- 실제 임시 A/B 계정과 실제 PNG 업로드·WebP 처리로 익명 공개 조회, 비공개 전환 후 이미지 404, 중복 좋아요·댓글, 팔로우 전/후 스토리 사진 404/200, 해제 후 404, 조회 수 1, 삭제 후 차단·파일 정리·용량 회수를 확인했다. 임시 파일과 계정은 모두 삭제했다. 실제 벽시계 24시간 대기는 하지 않았으며 만료 시각 검사는 로컬 PostgreSQL에서 수행했다.
- Chromium 모의 API 검사에서 스토리 열기·일시 정지·Escape·업로드·팔로우 해제와 공개 상세 댓글/좋아요·댓글 삭제가 통과했다. 375px 가로 넘침 없음과 원형 사진 목록을 확인했다.
- 최종 Chromium 전체 회귀 검사 65개가 한 번의 전체 실행에서 통과했다. 기존 로컬 작성·백업/복원·성장·언어/테마·화면 크기·인증/클라우드 흐름을 포함한다.
- 타입·변경 파일 ESLint·Prettier·별도 깨끗한 출력 폴더 빌드가 통과했다. 기존 Windows dist 파일 잠금과 약 851kB JS 번들 경고는 남아 있다.

이메일/복구·SMTP, 자동 정리 스케줄, 콘텐츠 신고·차단, 공개 출시 운영, 실제 휴대전화에서 두 계정 간 스토리 사용 확인은 후속 작업이다.
