# 앱 내부 알림과 로컬 자료 이전

2026-10-15. 후속 계획의 3차·4차 구현 및 실제 개발 Supabase 반영 기록이다.

## 사용 방법

- 홈 상단 하트의 숫자는 읽지 않은 실제 알림 수다. 하트와 `/activity`에서 팔로우·좋아요·댓글 알림을 보고 개별 읽음·모두 읽음을 처리한다. 비로그인 상태에서는 로그인으로 안내한다.
- 알림 숫자는 처음 진입, 창으로 돌아올 때, 읽음 처리 후, 화면이 보이는 동안 45초 간격으로 갱신한다. 알림 목록은 새로고침과 30개 단위 더 보기를 제공한다.
- 로그인 후 My의 `기기 자료를 클라우드로 이전` 또는 `/myaccount/import`에서 시작한다. 현재 주소의 브라우저 자료 또는 기존 JSON 백업을 미리보기로 읽는다. localhost 등 다른 주소에서 작성했다면 그 주소에서 백업을 내려받아 공개 사이트에서 선택한다.
- 항목 수와 펫 연결을 확인하고 체크한 뒤 이전한다. 로컬 펫은 새 클라우드 펫으로 만들거나 기존 펫에 연결한다. 예시 펫의 게시물은 실제 등록한 클라우드 펫을 직접 선택한다.
- 게시물은 비공개로 복사한다. 성장 기록과 게시물의 원본 날짜·태그를 보존하고, 기기 댓글·좋아요는 본인 전용 원본 자료로만 보관한다. 공개 댓글이나 좋아요 수로 등록하지 않는다.
- My의 `이전 자료 보관함`에서 원본 댓글·날짜·태그와 펫 사진을 확인한다. 기존 클라우드 펫에 연결해도 이름·사진을 덮어쓰지 않는다. 보관함의 펫 사진은 해당 계정만 읽으며 공개 프로필 사진으로 노출되지 않는다.
- 오류 난 항목은 같은 자료로 재시도한다. 완료된 항목은 수정하거나 다시 만들지 않는다. 같은 출처 ID의 내용·사진·연결이 바뀌면 충돌로 안내한다. 이미 삭제한 클라우드 기록도 재시도로 되살리지 않는다.
- 중지 버튼은 현재 항목 처리 후 멈춘다. 화면을 떠나거나 계정이 바뀌면 후속 작업을 멈춘다. 재진입 후 같은 자료를 선택하면 서버 이력을 기준으로 이어간다. 기기 메타데이터와 사진은 삭제·교체하지 않는다.

## 서버 경계

`202610150005_notifications.sql`, `202610150006_local_import.sql`을 기존 마이그레이션 다음에 적용했다. 이미 적용한 SQL을 다시 실행하지 않는다. 새 Edge 함수나 Docker는 필요 없다.

알림은 팔로우·좋아요·댓글의 INSERT 트리거에서 같은 트랜잭션으로 생성한다. 수신자·행동자·종류·원본 대상의 고유 제약으로 재시도 중복을 막고 자기 알림을 제외한다. 반응 취소, 댓글 삭제, 게시물 삭제·비공개, 비활성 행동자는 조회·읽음 API에서 재검사한다. 댓글 본문·게시물 본문·사진은 알림 응답에 포함하지 않는다. 재팔로우·재좋아요는 기존 알림의 읽음 상태를 유지한다.

이전 이력은 계정·종류·원본 ID로 고유하다. 원본 JSON과 사진 SHA-256을 비교하고, 준비→사진 첨부→항목 완료를 구분해 저장한다. 항목 완료와 실제 기록 생성은 같은 트랜잭션이다. 첨부된 ready 사진은 재시도에 재사용한다. 저장 이력은 본인 전용 RPC로만 조회하고 일반 테이블 접근은 차단한다. 원본 보관함은 클라우드 기록 편집·삭제와 독립적으로 유지한다.

기존 사진 제한과 처리 경로를 재사용한다. 한 장 5 MiB, 계정 50 MiB와 서비스 전체 예약 한도가 적용된다. 이전 이력은 계정당 최대 5,000개, 항목 JSON은 32 KiB다. 한도 초과는 실패 항목으로 남고 완료한 항목·기기 원본은 유지한다. 사진 업로드와 이력 첨부 사이에 브라우저가 비정상 종료하면 미사용 사진이 남을 수 있다. `/cloud`의 미사용 사진 삭제·정리로 처리하며 실제 파일 제거 전 용량을 반환하지 않는다. 완료된 원본 펫 사진은 보관함에서 계속 보존하므로 일반 미사용 정리에서 보호한다.

## 검증

- PostgreSQL 권한·통합 검사 41개 통과. 신규 검사는 알림 중복/자기 행동/읽음·취소·비공개·페이지 경계와 이전 소유권·변경 출처 충돌·사진 보호·재개·원본 보존·삭제 후 재생성 방지를 포함한다.
- 실제 Supabase에서 임시 A/B 계정 두 개와 PNG→WebP 사진으로 펫·게시물·성장 이전, 같은 자료 재시도, 다른 계정 거절, 비공개 원본 메모, 서버 생성 알림·읽음·비공개와 취소 후 차단을 확인했다. 테스트 파일과 계정을 정리했다.
- 기존 전체 앱 단위 검사 37개 파일/189개 통과 후, 추가 이전 검사 3개와 최종 관련 9개를 통과했다. Chromium 전체 70개를 통과했고 사진 첨부 뒤 등록 실패→재시도에서 재업로드가 없음을 확인했다. 타입·전체 린트와 별도 출력 폴더 production build를 확인했다. Windows 기존 dist 파일 잠금과 약 885kB 청크 경고는 후속 작업이다. 공개 배포 최종 확인은 진행 보드에 기록한다. 브라우저의 모의 API 화면 검사와 실제 HTTP 통합 검사를 구분한다. 실물 휴대전화 검증으로 간주하지 않는다.
