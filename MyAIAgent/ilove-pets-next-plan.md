## P2·P3 실행 결과

- 성장 기록 날짜·체중·메모 수정과 취소, 기록 ID 유지, 달력 오늘 이동·선택 날짜와 빈 날짜 안내를 제공한다. 관찰 기록은 로컬 날짜 기준 과거부터 오늘까지 허용한다.
- 첫 사용자 등록·작성 흐름과 데모/로컬 구분, 사진 용량·브라우저 저장 공간 추정·백업 우선 오류 안내를 추가했다.
- 사진을 단일 트랜잭션으로 조회하고, 200개 게시물 시나리오에서 DB 열기 4회와 Blob URL 200개 해제를 확인했다. 서로 다른 대용량 사진이나 실제 모바일 전체 성능을 검증한 결과는 아니다.
- TypeScript·ESLint·Prettier·빌드, Vitest 173개, Chromium Playwright 60개 통과. 완료 기준과 실행 근거는 진행 보드에 기록했다.

## P0 — 현재 작업본 검증과 마일스톤 확정

완료한 실행 범위다. 이후 회귀 검증에서도 아래 흐름을 유지한다.

1. `npm run typecheck`, `npm run lint`, `npm run test:run`, `npm run build`를 실행한다. 포맷은 변경 소스·테스트·문서부터 확인하고 전체 포맷 검사 실패 시 기존 문제와 이번 변경을 구분한다.
2. `npm run smoke:preview`로 기존 화면 회귀와 로컬 콘텐츠 흐름을 검증한다. preview가 이번 빌드를 제공하는지 확인하여 이전 서버 재사용으로 생기는 오검증을 피한다.
3. 다음 사용자 시나리오를 통과시키고 날짜·결과·증거 경로를 기록한다.
   - 펫 등록 → 사진 게시 → Home/My/Explore/상세 → 새로고침 후 유지.
   - 펫 이름·카테고리 변경 → 연결 게시물과 필터 갱신.
   - 게시물 수정, 삭제 취소·확정, 연결 게시물 삭제 전 펫 삭제 차단, 사진 Blob 정리.
   - 좋아요·댓글과 성장 기록 저장 → 새로고침 후 유지.
   - 잘못된 이미지·5MB 초과·초안 복원과 사진 재선택·메타데이터 손상·초기화 취소/확정.
4. 현재 테스트가 충분히 확인하지 않는 위험을 보완한다: 실제 두 탭 동시 저장, 저장 용량 부족, 사진 삭제 실패 후 재시도, 사진 누락, 중복 제출. Web Locks 미지원 시 현재 큐는 같은 탭 내 직렬화이므로 다른 탭 간 충돌 방지는 별도로 판단한다.
5. 375/768/1280px, ko/ja/en, light/dark에서 핵심 폼·오류·삭제 확인·달력을 확인한다. 현재 레이아웃 테스트는 언어별로 색상 모드를 다르게 선택하므로 각 언어의 두 테마 전체 검증으로 간주하지 않는다. 키보드 포커스와 모달 닫힘도 확인한다.
6. README의 하단 메뉴를 Community 구성과 맞추고 원본 기획서의 이미 구현된 릴스·캡션 UI·커뮤니티·PWA 항목을 현재 상태와 맞춘다. 과거 통과 수치를 이번 작업본 검증처럼 표시하지 않는다.
7. 변경 범위를 리뷰한다. 미추적 기능 소스·테스트 누락을 확인하고 `.omo` 실행 상태 및 임시 스크립트는 제품 변경과 구분한다. 검증 후 기능·테스트·문서를 리뷰 가능한 커밋 단위로 정리한다.

완료 기준: 필수 검사 통과, 핵심 흐름 브라우저 재현, 현재 날짜의 검증 기록, 관련 소스·테스트·문서 커밋. 해결되지 않은 제한은 따로 기록하고 검증 완료로 표시하지 않는다.

## P1 — 로컬 데이터 백업·복원

P0 이후 구현·검증했다. 초기화에 더해 사이트 데이터 삭제나 브라우저 변경에 대비한 백업을 제공한다.

- My의 로컬 데이터 관리에 백업 다운로드와 복원 진입점을 추가한다.
- 펫·게시물·좋아요·댓글·성장 기록 및 사진을 포함하고 형식 버전을 기록한다. 테마·언어·임시 작성 초안은 첫 버전의 백업 대상에서 제외한다.
- 복원 전 형식·버전·참조 관계·사진·용량을 검증하고 펫/게시물/기록 수와 사진 포함 여부를 보여준다.
- 첫 버전은 기존 데이터 전체 교체로 제한한다. 기존 데이터 백업을 안내하고 명시적 교체 확인 뒤 실행한다. ID 병합은 후속으로 남긴다.
- 복원 중 쓰기 작업을 통제하고 사진·메타데이터 임시 준비 후 전환 등 실패 복구 정책을 설계한다. 실패·취소 시 기존 데이터를 보존한다.
- 파일 형식과 허용 용량은 현재 사진 저장량을 측정한 뒤 결정한다.

완료 기준: 백업 → 빈 브라우저에 복원 → 사진·기록·반응 확인 → 새로고침 후 유지. 잘못된 파일·지원하지 않는 버전·저장 실패·취소로 기존 데이터가 손상되지 않는다.

## P2 — 성장 기록 수정과 달력 사용성 (완료)

- 기존 기록의 날짜·체중·메모 수정과 저장/취소를 제공한다.
- 같은 날짜에 여러 기록을 허용하는 현재 모델을 유지한다. 수정 시 ID를 보존하고 목록·차트·달력에 함께 반영한다.
- 오늘로 이동, 선택 날짜 표시, 기록 없는 날짜 안내를 보강한다.
- 과거·미래 날짜 허용 정책을 화면과 검증에 일치시키고 월말·연말·윤년·시간대 경계를 확인한다.
- 기존 차트의 로컬 기록 연결을 확인하고 체중 없는 돌봄 메모를 체중 데이터로 취급하지 않는다.

완료 기준: 추가 → 날짜 선택 → 수정 → 삭제가 목록·차트·달력에서 일치하고 다른 펫의 기록은 영향을 받지 않는다.

## P3 — 첫 사용 흐름과 저장 상태 안내 (완료)

- 빈 My 화면의 펫 등록 → 첫 게시 안내를 확인하고 Create의 펫 미등록 상태에서 등록 화면으로 연결한다.
- 로컬 데이터와 데모 데이터 구분을 Home/Explore/My/상세에 일관되게 표시한다.
- 데이터 수·사진 용량과 저장 오류 시 다음 행동을 안내한다. 용량 추정은 브라우저 지원 범위를 확인한 뒤 제공한다.
- 많은 게시물·사진에서 초기 로딩, Blob URL 해제, 스크롤을 측정하고 확인된 병목만 개선한다.

완료 기준: 첫 방문자가 펫 등록부터 게시까지 진행하고 로컬 저장 범위와 백업 방법을 이해할 수 있다.

## 별도 서버 마일스톤

S0 설계 후 사용자 지시에 따라 S1 로컬 구현을 진행했다. [서버 설계안](./ilove-pets-server-design.md)과 [설정 안내](./ilove-pets-server-setup.md)에 모델·권한·API·연결 절차를 기록했다. 실제 Supabase 적용·Google/SMTP 통합 검증은 준비 이후 수행한다.

1. Supabase 개발 프로젝트 설정과 Google·이메일/비밀번호 인증, DB/Storage 접근 권한 통합 검증을 마친다.
2. 로그인 → 펫 등록 → 게시 → 공개 상세 URL의 최소 흐름 구현.
3. 로컬 데이터 이전, 기기 간 동기화, 공개 공유 확장.

실제 AI API, GPS 산책, 커머스, 카카오 SDK 공유, PC 전용 레이아웃은 이번 후속 범위에 추가하지 않는다.
