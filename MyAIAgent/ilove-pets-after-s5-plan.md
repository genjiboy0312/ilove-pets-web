# S5 이후 개발 계획

업데이트: 2026-10-15

## 현재 판단

공개 배포본은 S4와 UI 개선까지다. S5는 운영 코드와 로컬 검증을 준비했으며 실제 서버 적용·전체 계정/사진 백업은 승인 대기다. [S5 적용·검증 안내](./ilove-pets-operations.md)를 먼저 완료한다. 아래 기능은 이번에 추가 개발하지 않고 후속 계획으로만 남긴다.

## 먼저 닫을 운영 확인 항목

| 우선순위 | 작업 | 완료 기준 |
| --- | --- | --- |
| P0 | 대상/범위 승인 후 S5 서버 적용과 예약 실행 | 임시 A/B/익명 계정으로 삭제·신고·차단·이미지 차단 확인. 앱 방문 없이 정리 실행 |
| P0 | SMTP·발신 도메인·메일 실수신 | 가입 확인·비밀번호 복구·만료 링크·Google/이메일 계정 연결을 실제 수신함에서 확인 |
| P0 | 별도 빈 프로젝트 복원 연습 | Auth 재로그인, RLS, DB 행 수, 사진 바이트/해시 일치와 원본 프로젝트 보존 |
| P0 | 실제 모바일 2대 확인 | A 기록/공개 → B 팔로우·스토리·댓글 → A 알림 → 비공개/차단·삭제 반영 |
| P1 | 운영 문의처·보관 정책·신고 담당 확정 | UI/문서의 연락·보관 안내가 실제 운영과 일치. 미해결 신고 처리 책임 명확화 |

위 항목이 남아 있으면 운영 출시 완료로 표시하지 않는다.

## 다음 개발 추천: S6 실제 커뮤니티 연결

현재 커뮤니티는 디자인과 샘플 콘텐츠를 보여 준다. 포트폴리오에서 한 흐름을 끝까지 보여 주려면 이 화면을 실제 서버와 연결하는 가치가 크다.

- 게시판 글은 사진 일기와 분리한 모델로 설계한다. 자유 글·질문 등 텍스트 중심 글을 펫 등록 없이도 작성할 수 있게 하되, 필요하면 본인 펫을 연결한다.
- 글 작성·수정·삭제, 카테고리·최신순, 커서 페이지 조회를 구현한다. 사진은 현재 검증/비공개 버킷 파이프라인과 용량 제한을 재사용한다.
- 댓글·신고·차단·작성자 프로필 이동은 S5 경계와 통합한다. 샘플은 데모 표시를 유지하며 실제 글로 위장하지 않는다.
- 글 공개 정책, 익명 조회 허용, 댓글/삭제 권한과 신고 숨김의 범위를 구현 전에 확정한다.

완료 기준: A가 글/사진 작성 → B가 다른 기기에서 조회·댓글 → A 알림 → A 수정/삭제 → B 갱신에 반영. B의 타인 글 수정·비공개 파일 접근은 거절한다. 오프라인·실패·재시도와 모바일/다국어 화면도 확인한다.

## S7 발견과 기록 사용성

| 작업 | 목표 | 완료 기준 |
| --- | --- | --- |
| 서버 검색 | 사용자·공개 글·커뮤니티를 구분한 검색 | 비공개/숨김/차단 대상 제외, 페이지 이동 중 중복 없음 |
| 펫별 기록 | 내 펫 상세에서 사진·성장·케어를 연결 | 펫 필터와 달력·그래프 일치, 원본 기록 보존 |
| 실패 복구 | 업로드·내보내기·이전 상태를 더 명확히 표현 | 재시도 시 중복 생성 없음, 계정 전환 시 이전 작업 결과가 섞이지 않음 |

사용자 백업의 범위를 확장하려면 현재 제외하는 프로필·펫 원본 사진·스토리·소셜 이력의 보관 정책과 복원 시 공개 여부부터 정한다. 무조건 같은 JSON에 합치지 않는다.

## S8 포트폴리오 마무리

- 운영자 신고 검토 화면은 별도 역할·감사 기록을 먼저 설계하고, 브라우저에 관리자 키를 배포하지 않는다.
- 검증용 A/B 계정 또는 로그인 없이 볼 수 있는 데모 경로, 화면별 시나리오와 README 캡처를 최신화한다.
- CI에서 타입·앱·서버·핵심 브라우저 검사를 묶고, 번들/사진 예산과 접근성·키보드·실물 모바일 결과를 기록한다.
- 실제 구현/모의 검사/실제 서비스 검증을 구분하고 남은 과제를 한눈에 보이게 정리한다.

## 이번 후속에서 확장하지 않는 범위

동영상/릴스 서버, DM, GPS 산책, 커머스, AI API, 유료 인프라는 필요성과 비용을 별도로 검토한다. 실제 병원 운영 정보는 제공처·갱신·정확성 검증이 준비되기 전까지 샘플 안내를 유지한다.
