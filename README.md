# 🐾 iLove Pets

> 반려동물을 사랑하는 사람들을 위한 모바일 웹 커뮤니티 · 프론트엔드 데모 프로젝트

**iLove Pets**은 강아지, 고양이, 파충류, 조류 등 모든 반려동물의 일상을 공유하는 SNS를 그대로 옮겨 본 모바일 웹 애플리케이션입니다.
실제 서비스 수준의 화면과 사용자 경험(UX)을 프론트엔드만으로 구현하는 것을 목표로 하며, 백엔드 없이도 **실제 앱처럼 동작하는 인터랙션**(좋아요, 댓글, 공유, 테마·언어 전환 등)을 체험할 수 있습니다.

서버 전환 S1 작업본에는 Supabase Google·이메일/비밀번호 인증 UI와 DB/권한 마이그레이션을 추가했습니다. 실제 프로젝트 연결 전에는 로컬 모드로 동작합니다. [서버 설정과 검증 범위](MyAIAgent/ilove-pets-server-setup.md)를 참고하세요.

S2 작업본의 `/cloud`는 로그인 계정 전용 펫·성장 기록·비공개 사진 게시물 CRUD를 제공합니다. 추가 SQL 적용과 사진 함수 배포가 필요하며 기존 로컬 자료는 자동 이전하지 않습니다. 실제 원격 검증 상태와 적용 순서는 [클라우드 설정 안내](MyAIAgent/ilove-pets-cloud-setup.md)에 기록합니다.

## ✨ 이 프로젝트는 무엇인가요?

> 💡 **한 줄 요약**: "인스타그램 + 반려동물"을 모바일에서 그대로 경험할 수 있는 데모 앱입니다.

비개발자분들은 아래 세 가지만 기억하시면 됩니다.

1. **스마트폰 앱처럼 동작하는 웹사이트입니다.**
   하단에 홈 / 탐색 / 작성 / 커뮤니티 / 내 계정 다섯 개의 메뉴가 있고, 손가락으로 스크롤하며 피드를 내리는 익숙한 경험을 그대로 제공합니다. 활동 알림은 화면 상단 하트 버튼에서 열 수 있습니다.

2. **누르면 반응하는 진짜 기능들이 들어 있습니다.**
   ♥ 좋아요 누르기, 💬 댓글 달기(입력하면 바로 목록에 추가), 📤 공유하기(X·페이스북은 실제 공유 창 연결), 🌙 다크 모드, 🌏 한국어/일본어/영어 3개 국어 전환까지 모두 동작합니다.

3. **연습용(데모) 데이터와 브라우저 로컬 저장을 함께 사용합니다.**
   회원가입 없이도 미리 준비된 게시물과 반려동물을 둘러볼 수 있고, 내 브라우저에서 직접 등록한 펫과 게시물은 새로고침 후에도 유지됩니다. 서버나 계정 동기화는 아직 연결되지 않았습니다(아래 로드맵 참고).

| 이런 분께 추천해요 | 이유                                                                          |
| ------------------ | ----------------------------------------------------------------------------- |
| 🙋 일반 사용자     | 설치 없이 브라우저에서 반려동물 SNS를 체험할 수 있어요                        |
| 🧑‍💼 기획자          | 모바일 앱 UX 흐름(피드 → 상세 팝업 → 댓글)을 그대로 관찰할 수 있어요          |
| 👩‍💻 개발자          | React 19 + TypeScript + Vite 기반의 깔끔한 프론트엔드 구조를 참고할 수 있어요 |

## 🗺️ 화면 둘러보기

앱은 하단 네비게이션의 5개 화면과 설정 화면으로 구성됩니다.

### 🏠 홈 (Home)

- **반려동물 카테고리 필터**: `전체 · 강아지 · 고양이 · 파충류 · 조류 · 소동물 · 기타` 칩을 누르면 피드가 즉시 필터링됩니다.
  - 좌우 `<` `>` 화살표로 칩을 넘길 수 있고, 스트립은 **스크롤해도 상단에 고정**되며 뒤에 지나가는 콘텐츠가 **흐릿하게 비치는 글래스 효과**로 UI가 자연스럽게 분리됩니다.
- **게시물 카드**: 프로필 · 사진 · 본문 · 해시태그 · 좋아요/댓글/공유 버튼
  - ♥ 좋아요는 즉시 반영되고, 💬 **댓글 버튼을 누르면 게시물 사진과 댓글이 함께 나오는 중앙 팝업**이 열립니다. 여기서 댓글을 입력하면 목록에 실시간으로 추가됩니다.

### 🔍 탐색 (Explore)

- **인스타그램 스타일 3열 이미지 그리드**: 이미지만 가독성 있게 배치됩니다.
- **무한 스크롤**: 아래로 계속 내리면 타일이 자동으로 추가됩니다.
- **타일 클릭 시** 홈의 댓글 팝업과 같은 상세 팝업으로 해당 게시물을 바로 볼 수 있습니다.

### ➕ 작성 (Create)

- 내 계정에서 등록한 펫을 선택하고, 사진 파일을 고른 뒤 본문과 태그를 입력해 **이 브라우저에 로컬 게시물로 저장**합니다.
- 사진은 `IndexedDB`에 Blob으로 저장하고, 본문·선택 펫·태그 초안은 `localStorage`에 보존됩니다. 사진 초안 파일은 새로고침 후 복원되지 않으므로 다시 선택해야 합니다.
- 지원 형식은 JPEG/PNG/WebP, 5MB 이하이며 브라우저가 실제 이미지로 디코딩할 수 있는 파일만 게시할 수 있습니다.

### 🔔 활동 (Activity)

- 좋아요·댓글·팔로우 알림 피드.

### 💬 커뮤니티 (Community)

- **게시판 / 병원 지도 탭**: 커뮤니티 게시글 목록과 Leaflet 기반 동물병원 지도를 같은 화면에서 전환합니다.
- **동물병원 지도**: 시·구·동 필터와 `야간 응급만 보기` 필터가 지도 핀과 병원 목록을 함께 갱신합니다.
- 병원명, 진료 시간, 전화 링크는 **데모용 샘플 데이터**이며 실제 병원 정보로 검증된 내용이 아닙니다.

### 👤 내 계정 (My)

- 프로필, 통계, **등록 펫 / 내 게시물 섹션은 접었다 펼칠 수 있습니다.**
- **내 펫 등록** 폼에서 이름·카테고리·품종을 입력하고 선택적으로 사진을 추가하면 즉시 등록 펫 목록과 작성 화면 펫 선택지에 반영됩니다.
- 로컬 게시물은 내 게시물 그리드에도 표시되며, 타일을 누르면 기존 상세/댓글 팝업과 같은 화면으로 열립니다.
- 직접 등록한 펫·게시물을 수정·삭제하고 체중·돌봄 메모를 기록할 수 있습니다. 성장 달력에서 날짜별 기록을 확인합니다. 연결 게시물이 있는 펫은 게시물을 먼저 삭제해야 합니다.
- 성장 기록의 날짜·체중·메모를 수정하거나 취소할 수 있고, 달력에서 오늘로 이동할 수 있습니다. 관찰 기록은 과거부터 오늘까지 저장하며 같은 날짜의 여러 기록도 유지합니다. 체중 없는 돌봄 메모는 차트에서 제외합니다.
- **이 기기의 데이터**에서 실제 로컬 펫·게시물·기록 수와 저장 사진의 개수·용량을 확인합니다. 지원하는 브라우저는 캐시를 포함한 저장 공간 추정치도 제공합니다. 데모 예시와 직접 저장한 콘텐츠는 별도 표시합니다.
- **백업과 복원**에서 펫·게시물·사진·좋아요·댓글·성장 기록을 JSON 파일로 다운로드합니다. 복원 전 개수와 사진 용량을 확인하고, 교체를 확정하면 현재 로컬 데이터를 백업 내용으로 바꿉니다. 잘못된 파일·취소·저장 실패는 기존 데이터를 교체하지 않습니다.
- **팔로워·팔로잉 숫자를 누르면** 유저 목록 팝업이 열립니다.
- 우측 상단 ⚙️ 버튼으로 설정 화면에 진입합니다.

> 🔒 로컬 저장 범위: 직접 등록한 펫과 게시물은 현재 브라우저의 사이트 데이터에만 저장됩니다. 브라우저의 사이트 데이터/캐시를 지우거나 다른 기기·다른 브라우저에서 열면 사라질 수 있습니다. 로그인, 공개 URL 공유, 기기 간 동기화는 서버가 필요한 다음 단계입니다. 서버가 없는 로컬 게시물은 공유 버튼에 “이 기기 전용”으로 표시되며 공개 링크처럼 공유되지 않습니다.

백업 파일에는 개인 사진과 기록이 들어 있으므로 안전하게 보관하세요. 파일 100MB, 사진 합계 64MB, 사진 한 장 5MB까지 처리합니다. 테마·언어·작성 초안은 백업에 포함하지 않으며 복원에서도 변경하지 않습니다. 복원은 병합 없이 전체 교체하며, 여러 탭의 쓰기를 보호하는 Web Locks 지원이 필요합니다. 복원 중에는 기존 사진과 새 사진을 함께 보관할 여유 공간이 필요합니다. 사진이 누락되거나 메타데이터 일부가 손상된 경우 완전한 백업으로 내보내지 않고 오류를 표시합니다.

### ⚙️ 설정 (Settings)

- **테마(시스템/라이트/다크)** 와 **언어(한국어/日本語/English)**: 행을 누르면 선택 리스트박스 팝업이 열리고, 선택 즉 적용되며 행에 현재 값이 표시됩니다.
- 개인정보 처리방침 · 이용약관 · 정보 팝업, 알림 on/off 스위치, 로그아웃/계정 삭제 버튼(UI 데모).

> ♿ 접근성도 챙겼습니다: 팝업은 `role="dialog"`/`role="listbox"` 등 의미 있는 역할을 사용하고, Esc 키와 뒷배경 클릭으로 닫히며, 스크린 리더가 읽을 수 있는 라벨을 제공합니다. `prefers-reduced-motion` 설정도 존중합니다.

## 🚀 직접 실행해 보기

### 준비물

- [Node.js](https://nodejs.org/) **20.19 이상** (LTS 권장)

### 실행 방법 (3단계!)

```bash
# 1) 이 저장소를 내려받습니다.
git clone https://github.com/genjiboy0312/ilove-pets-web.git
cd ilove-pets-web

# 2) 필요한 패키지를 설치합니다. (처음 한 번만)
npm install

# 3) 개발 서버를 실행합니다.
npm run dev
```

터미널에 표시되는 주소(예: `http://localhost:5173`)를 브라우저로 열면 끝!
📱 브라우저 개발자 도구(F12) → 휴대폰 아이콘을 누르면 **모바일 화면으로** 더욱 생생하게 볼 수 있습니다.

### 배포본 확인하기

```bash
npm run build      # dist/ 폴더에 최적화된 결과물이 생성됩니다.
npm run preview    # 빌드 결과물을 로컬 서버로 미리 보기합니다.
```

preview 주소는 `http://127.0.0.1:5174/`이며 서버 터미널을 계속 실행해 두어야 합니다. 코드 변경 후에는 다시 빌드하고 브라우저를 새로고침하세요. 앱 스크립트를 불러오지 못하면 재시도 안내를 표시하며, 폰트 서버 오류는 앱 시작을 막지 않습니다. 로컬 데이터 삭제 없이 서비스 워커를 갱신합니다.

| `npm test` / `npm run test:run`         | 컴포넌트·데이터 단위 테스트 (**Vitest**, 100+ 테스트)               |

## 📁 폴더 구조

```
ilove-pets-web/
├── public/                  # 정적 파일
├── src/
│   ├── components/          # 여러 화면이 공유하는 공통 컴포넌트 (앱 셸, 이미지 등)
│   ├── constants/           # 카테고리 등 고정 상수
│   ├── features/            # 화면(도메인)별 코드 — 각 폴더가 하나의 화면
│   │   ├── home/            #   홈: 피드, 게시물 카드, 댓글 팝업
│   │   ├── explore/         #   탐색: 3열 이미지 그리드, 무한 스크롤
│   │   ├── create/          #   작성
│   │   ├── activity/        #   활동 알림
│   │   ├── my/              #   내 계정: 프로필, 등록 펫, 내 게시물
│   │   └── settings/        #   설정: 테마/언어/약관 팝업
│   ├── i18n/                # 다국어 문구 리소스 (ko/ja/en)
│   ├── mocks/               # 데모용 가짜 데이터 (게시물·펫·유저·댓글)
│   ├── styles/              # 화면별 CSS (디자인 토큰 기반)
│   ├── theme/               # 라이트/다크 테마 상태 관리
│   └── types/               # 도메인 타입 정의
└── MyAIAgent/               # 개발 계획·진행 현황 문서
```

> 각 `features/*` 폴더 안에는 화면(`*.tsx`)과 그 화면 전용 데이터 함수(`*Data.ts`)·테스트(`*.test.tsx`)가 함께 있어, **하나의 기능을 한 폴더에서 파악**할 수 있습니다.

## 🏗 아키텍처 하이라이트 (개발자용)

면접·코드 리뷰에서 질문이 나올 만한 구현 포인트들입니다.

- **디자인 토큰 기반 스타일**: 색·간격·radius를 CSS 변수(`--color-*`, `--space-*`)로 통일했습니다. 다크 모드는 `data-theme` 속성 한 번으로 전체 토큰을 교체합니다.
- **모달 = body 포털 + 중앙 고정**: 모든 팝업(댓글·공유·설정 시트)은 `createPortal(document.body)`로 렌더링됩니다. 임의 조상의 `transform`이 `position: fixed`의 containing block을 만들어 팝업이 엉뚱한 위치에 뜨는 브라우저 동작을 구조적으로 차단합니다.
- **리스트박스 접근성**: 테마/언어 선택은 `role="listbox"` + `aria-selected` 옵션으로 구현해 키보드·스크린리더와 호환됩니다.
- **무한 스크롤 페이지네이션**: IntersectionObserver 센티널 + 페이지 단위 순환(cycle) 생성기로, mock 데이터 4개로도 끊김 없는 무한 피드를 재현합니다.
- **글래스모피즘**: `backdrop-filter: blur()` + `color-mix()` 반투명 배경으로 카테고리 스트립·헤더 버튼에 자연스러운 분리감을 주고, 미지원 브라우저용 `@supports` 폴백을 두었습니다.
- **타입 안전 데이터 계층**: `types/domain.ts`에 템플릿 리터럴 타입(`PostId = \`post_${string}\``)을 정의해 ID 혼용을 컴파일 타임에 차단하고, 모든 mock 데이터에 불변식 테스트를 뒀습니다.
- **브라우저 로컬 저장 경계**: 로컬 펫/게시물 메타데이터는 `localStorage`에서 파싱하고, 사진 Blob은 `IndexedDB`에 저장합니다. 화면에는 Blob을 `URL.createObjectURL()`로 연결하고 컴포넌트 생명주기에 맞춰 해제합니다.
- **사진 스냅샷 조회**: 메타데이터와 사진 참조를 공유 락 안에서 확보하고, 서로 다른 사진 키를 한 번의 IndexedDB 트랜잭션으로 읽습니다. 복원과 로딩이 겹쳐도 읽은 Blob 스냅샷을 유지합니다.
- **다국어 타입 안전성**: `resources.ts`를 단일 소스로 두고 i18next 타입을 연결해, 존재하지 않는 문구 키는 컴파일 오류가 납니다.
- **PWA 캐시 갱신**: 앱 번들과 독립적인 시작 스크립트에서 워커를 갱신합니다. 네트워크 우선 전략과 `skipWaiting()`을 유지하고, HTML 대체 응답은 탐색 요청에만 사용합니다. 누락된 JS/CSS에 HTML을 반환하거나 캐시하지 않습니다.
- **복원 실패 보호**: 공유 Web Lock 안에서 사진을 새 키로 먼저 저장하고 메타데이터를 마지막에 교체합니다. 실패 시 기존 사진과 메타데이터를 유지하고 임시 사진을 정리합니다. 참조되지 않는 사진은 다음 로드에서 정리를 재시도하며, 일부 레코드를 복구해 읽은 메타데이터의 사진은 자동 삭제하지 않습니다.

## 🗺 로드맵 & 진행 현황

프로필 사진·닉네임·소개 편집과 `/users/:username` 공개 프로필, My의 서버 기록·스토리 관리, 작성 화면의 로컬/클라우드 목적지, 계정별로 기억하는 팔로잉 피드, 스토리 스와이프·이미지 재시도를 지원합니다. [사용법과 검증 범위](./MyAIAgent/ilove-pets-profiles-feeds.md).

알림은 홈 하트 또는 `/activity`, 자료 이전은 My 또는 `/myaccount/import`에서 사용합니다. [사용법·서버 경계·검증 기록](./MyAIAgent/ilove-pets-notifications-import.md).
