# 포트폴리오 마무리 검증 기록

2026-10-15~16, `codex/s5-operations`의 S5와 포트폴리오 작업본을 대상으로 확인했습니다. 공개 사이트의 새 배포 검증이 아닙니다. 이전 S5의 실제 서버 변경·전체 백업은 여전히 승인 대기이며 SMTP 설정도 다음 단계로 미뤘습니다.

## 수행 결과

| 확인                       | 결과와 범위                                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 앱 단위 검사               | 40개 파일·195개 통과                                                                                          |
| production 빌드            | `npm run build` 통과, 최종 타입·변경 파일 린트 확인                                                           |
| 전체 Chromium              | 87개 중 86개 통과. 아래 측정 대기 문제를 보완한 뒤 나머지 1개 재검사 통과                                     |
| 신규 계정·모바일 추가 검사 | 로딩·빈 기록·첫 펫 저장·503 새로고침·360/390/430px 라이트/다크 5개 통과. 전체 검사에서도 재확인               |
| 영상 시나리오              | 전용 녹화 3개 통과, 실제 기기 저장 1편 + 모의 API 소셜/안전 2편                                               |

| 번들 비교                  | main `4986379` 복사본과 현재 작업본을 같은 설치 의존성·공개 인증 환경값으로 빌드                              |

격리 서버 56개 통과는 이전 S5 구현 검증 결과입니다. 이번 포트폴리오 마무리에서는 서버 코드를 변경하지 않았으며 새 원격 계정 생성·DB 마이그레이션·신고·차단·계정 삭제·전체 데이터 백업을 실행하지 않았습니다.

## 점검에서 보완한 부분

- 클라우드 안내에 남아 있던 공개 공유 미지원 문구를 현재의 선택적 공개·명시적 자료 복사 흐름에 맞췄습니다. 준비 오류도 내부 SQL 단계 대신 사용자가 이해할 수 있는 안내로 바꿨습니다. ko/en/ja를 함께 갱신했습니다.
- 사진 파일 입력의 12px 글꼴을 16px로 조정했습니다. 새 계정의 작성·관리 화면에서 가로 넘침과 입력 크기를 확인했습니다.
- 초기 503은 SDK의 자동 재시도 후 오류 안내가 나타나므로 검사에서 해당 응답 시간을 기다립니다. 사용자가 명시적으로 새로고침한 뒤 입력 폼이 복구되고, 실패를 저장 성공으로 표시하지 않는지 확인했습니다.
- 기존 대용량 피드 검사는 커뮤니티 링크 클릭 직후 Blob 해제 횟수를 읽었습니다. 지연 페이지 로딩 중에는 이전 화면이 남아 있을 수 있어 실제 Blob 할당과 목적 화면 표시·해제 완료를 기다린 뒤 측정하게 보완했습니다. 200개 게시물의 Blob 해제·0개 잔여·제한된 IndexedDB 열기 기준은 유지했습니다.
- 영상 시연의 좋아요 버튼은 성공 후 접근 가능한 이름이 ‘좋아요 취소’로 바뀌므로 변경된 이름과 상태를 함께 검사했습니다.
