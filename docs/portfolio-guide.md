# 포트폴리오 시연·검증 가이드

2026-10-15 작업본 기준입니다. 공개 사이트는 S4·UI 개선까지이고, S5 안전 기능은 로컬 구현·검증 상태입니다. 이메일 발송·복구는 SMTP 설정을 다음 단계로 미뤘습니다.

## 처음 보는 분을 위한 1분 안내

iLove Pets는 반려동물의 사진 일기와 성장 기록을 관리하고, 직접 공개한 기록으로 이웃과 소통하는 모바일 웹입니다. 로그인 없는 기기 기록과 계정 전용 클라우드 자료를 분리했습니다. 단순한 화면 제작을 넘어 소유권, 사진 접근, 실패 재시도와 자료 이전을 다뤘습니다.

1. [시연 영상 세 편](demo/README.md)으로 기기 기록·공개 소통·안전 기능을 확인합니다.
2. [공개 사이트](https://ilove-pets-web.pages.dev/)의 내 계정에서 기기 기록 사용을 선택하면 로그인 없이 직접 기록할 수 있습니다.
3. [기술 선택과 문제 해결](technical-decisions.md)에서 구현 근거와 남은 제약을 확인합니다.

## 대표 시나리오 1 · 처음 방문해서 첫 기록 남기기

**목적:** 계정 준비 없이도 제품의 핵심 가치를 경험합니다.

`내 계정 → 로그인 안내 → 기기 기록 사용 → 펫 등록 → 작성 → 사진·내용 입력 → 게시 → 홈 → 새로고침`

- 시작 조건: 빈 브라우저 저장 공간. 샘플 자료는 처음부터 보일 수 있으나 사용자 자료와 구분됩니다.
- 확인 기준: 직접 등록한 펫에 글을 연결하고 사진·본문을 표시하며 새로고침 후에도 유지합니다.
- 설명할 점: localStorage에는 메타데이터, IndexedDB에는 사진을 저장합니다. 다른 브라우저·사이트 주소와 자동 공유되지 않습니다.
- 클라우드 확장: Google 로그인 후 클라우드 펫·글을 관리합니다. 기기 원본은 명시적 가져오기 전까지 자동 업로드하지 않습니다.
- 증거: [영상 1](demo/01-device-journal.webm), [실제 로컬 저장 브라우저 검사](../tests/local-content.spec.ts), [빈 클라우드 계정 검사](../tests/portfolio-readiness.spec.ts).

Google OAuth 테스트 모드의 등록 사용자 제한이 있으므로, 면접관에게 본인 계정 비밀번호를 제공하지 않습니다. 등록되지 않은 방문자는 기기 기록과 촬영 자료로 확인할 수 있습니다. 이메일 신규 가입·비밀번호 복구의 실수신은 아직 검증하지 않았습니다.

## 대표 시나리오 2 · 선택한 글만 공유하고 소통하기

**목적:** 개인 기록과 공개 소셜의 경계를 보여 줍니다.

`A 로그인 → 클라우드 펫 등록 → 사진 글 비공개 저장 → 공개 확인 → B가 공개 글 조회·팔로우·좋아요·댓글 → A의 활동 알림 → 글 상세`

- 시작 조건: A/B 별도 계정과 A 소유의 준비된 사진 글.
- 확인 기준: 비공개 글은 B가 읽지 못하고, 공개 후 소통할 수 있으며 공개 취소 시 새 접근이 제한됩니다.
- 스토리 확장: 팔로우한 사용자의 홈 상단 원형 목록에서 사진을 보고 일시정지·넘김을 사용할 수 있습니다. 24시간 만료와 파일 물리 삭제는 별도 단계입니다.
- 설명할 점: 화면에서 버튼을 숨기는 것으로 권한을 대신하지 않습니다. RLS·RPC·사진 함수가 요청별 권한을 검사합니다.
- 증거: [영상 2](demo/02-public-social.webm)는 좋아요·댓글·프로필 **모의 API 화면 시연**입니다. 전체 A/B 실제 서버 시나리오의 새 녹화가 아닙니다. 기존 원격 확인 이력은 [알림·이전 기록](../MyAIAgent/ilove-pets-notifications-import.md), 권한 검사는 [격리 DB 검사](../tests/server/profiles.test.mjs)에서 확인합니다.

## 대표 시나리오 3 · 실패를 알리고 안전하게 복구하기

**목적:** 실패를 성공처럼 표시하지 않고, 민감한 작업은 사용자가 영향을 확인하게 합니다.

`공개 글 → 신고 사유·설명 → 요청 제한 오류 → 재시도 → 접수 확인 → 사용자 차단 → 영향 안내 → 두 번째 확인`

- 확인 기준: 429에서는 성공 안내를 표시하지 않습니다. 차단 첫 버튼만으로 요청하지 않고 두 번째 확인에서 실행합니다. 신고만으로 콘텐츠를 자동 숨기지 않습니다.
- 계정 삭제 확장: 설정에서 백업·삭제 범위 확인, 체크·DELETE 입력, 최근 로그인 검증을 거칩니다. 실계정 삭제를 영상으로 시연하지 않습니다.
- 증거: [영상 3](demo/03-safety-recovery.webm), [브라우저 안전 기능 검사](../tests/operations.spec.ts), [서버 권한·큐 검사](../tests/server/operations.test.mjs).
- **상태:** S5 로컬 작업본입니다. 실제 서비스의 신고·차단·예약 정리·계정 삭제가 운영 중이라는 의미는 아닙니다.

## 새 계정·모바일·오류 점검

자동 검사는 실제 화면·브라우저 저장을 사용하되 계정 서버 응답은 fixture로 통제합니다. 신규 Supabase 실계정을 만들거나 기존 이용자 자료를 변경하지 않습니다.

| 항목               | 자동 확인 범위                                                           | 실물 기기에서 남은 확인                  |
| ------------------ | ------------------------------------------------------------------------ | ---------------------------------------- |
| 비로그인 진입      | 로그인 안내, 관리 UI 숨김, 기기 기록 보조 진입                           | Safari/Chrome의 OAuth 왕복 후 복귀       |
| 신규 클라우드 계정 | 로딩 중 편집 폼 미노출, 빈 목록, 펫 등록 안내, 첫 등록 후 작성 폼 활성화 | 실제 새 A 계정 첫 프로필 생성            |
| 좁은 화면          | 360·375·390·430px 및 기존 768·1280px, 라이트·다크, 입력 글꼴·가로 넘침   | 가상 키보드·주소창·safe area·사진 선택기 |
| 오류 복구          | 초기 503→명시적 새로고침, 429→재시도, 청크 로딩 실패→복구 안내           | 느린 LTE·Wi-Fi 전환·백그라운드 복귀      |
| 저장               | 기기 사진·글·성장 기록 유지, 클라우드 모의 CRUD·중복 재시도              | 두 기기에서 실제 계정 동기화·버전 충돌   |

새 계정 화면: [빈 기록](screenshots/account-new-cloud.png) · [실패 후 새로고침 안내](screenshots/cloud-retry.png). 두 이미지 모두 로컬 production 미리보기와 모의 API로 촬영했습니다.

### 실물 휴대폰 최종 확인 순서

아래는 **미실행 체크리스트**입니다. 브라우저 에뮬레이션을 iPhone·Android 실물 통과로 표시하지 않습니다.

1. iPhone Safari와 Android Chrome에서 공개 주소를 열고, 로그인 안내·기기 기록을 확인합니다.
2. 등록된 Google 테스트 계정으로 로그인하고 페이지 복귀·새로고침·로그아웃을 확인합니다.
3. 사진 촬영/앨범 선택, 입력 중 키보드 겹침, 세로·가로 회전을 확인합니다.
4. 임시 A/B 계정으로 비공개→공개→댓글→알림→공개 취소를 확인합니다.
5. 느린 연결과 복귀 상황에서 중복 저장·다른 계정 자료 노출·빈 화면이 없는지 기록합니다.

결과는 기종·OS·브라우저 버전·날짜·문제 재현 경로와 함께 적습니다. SMTP 실수신, S5 실제 적용, 별도 호스팅 프로젝트 복원은 별도 승인·환경이 필요한 항목입니다.

## 재현 명령

이번 실행 결과와 점검에서 수정한 부분은 [마무리 검증 기록](portfolio-verification.md)을 참고하세요.

```bash
npm ci
npm run playwright:install
npm run build
npm run test:run
npm run test:server
npm run smoke:preview
npm run demo:record
```

`demo:record`는 `127.0.0.1:5178`의 production 미리보기에서 새 모바일 브라우저 컨텍스트를 열어 WebM 세 편을 갱신합니다. 계정 API는 모의 처리하고 미일치 외부 요청은 차단합니다. 공개 환경변수가 있는 빌드가 필요합니다. 실제 사용자 세션·비밀 키는 사용하지 않습니다.
